## 2025-02-23 - CSRF Vulnerability Mitigation with SameSite Cookies\n**Vulnerability:** The session cookies used for authentication were configured with `sameSite: "none"`, which allowed the cookies to be sent along with cross-site requests, making the application vulnerable to Cross-Site Request Forgery (CSRF) attacks.\n**Learning:** Even when the frontend and backend APIs share domains, using `sameSite: "none"` carelessly exposes the application to CSRF. It was identified during an internal review.\n**Prevention:** When the API and the web application share domains or subdomains, prefer using `sameSite: "lax"` (or `"strict"`) as it offers robust protection against CSRF without breaking legitimate cross-domain functionality.\n
